# RCA — kupi-kasir-pro production blank white page

## Verdict
Production is serving a **STALE, pre-fix frontend build**. The null-guard fix that was verified in preview is **NOT** in the live build. This is a "deploy lama" situation — needs a fresh redeploy, not a code or infra fix.

## Live run under investigation
- deployment: `kupi-kasir-pro` (frontend_type=cloudflare, template=fastapi_react_mongo_shadcn_base_image)
- active/live run: `0da9f392-31e1-454e-be00-8c6f2dd34282` (redeploy), built ~22:59 UTC, live 23:06 UTC
- URL: https://kupi-kasir-pro.emergent.host

## Evidence
1. **Served page + assets healthy**: `GET /` → 200, valid HTML referencing `/static/js/main.6cb17174.js` + CSS. `GET /api/` → 200 `{"service":"mjd-kupi","status":"ok","db":"supabase"}`.
2. **Backend fully healthy — no 5xx**: last 2h of logs show heavy 200 traffic incl. `POST /api/auth/login` 200, `/api/auth/me` 200, `/api/products?include_inactive=1` 200, `/api/outlets` 200, `/api/settings/*` 200, `/api/dashboard/analytics?...&outlet_id=all` 200. Only non-200s: internal `/health` probes 404 (backend has no /health route; nginx serves it — harmless) and `/api/auth/me` 401 before login (normal).
3. **Secrets all present & non-empty**: JWT_SECRET, DATABASE_URL, DB_NAME, MONGO_URL, REACT_APP_BACKEND_URL, CORS_ORIGINS, ADMIN_*, etc. Not a secret/env issue. (App's real datastore is Supabase via DATABASE_URL — not the deployed Mongo — so its data was not queried here.)
4. **DECISIVE — source pulled for the live build still has the bug.** Read via eph sandbox from run `0da9f392`'s pulled source:
   - `frontend/src/App.js:532` → `<span>{p.vendor} · {p.outlet_id.replace("outlet-", "")}</span>`  ← unsafe, no null-guard
   - `grep 'outlet_id ?'` / `grep 'semua outlet'` → the fixed pattern is **not present** anywhere in App.js.

## Root cause
The live production image `0da9f392` was built from source pulled BEFORE the null-guard fix was committed to preview. A global product with `outlet_id = NULL` (permitted since iter30) reaches the Overview low-stock render, `null.replace(...)` throws `TypeError: Cannot read properties of null (reading 'replace')`, and the unguarded React render blanks the page. (Reported at line 546 in preview; it is line 532 in this build — same statement.)

## Resolution
No fix to apply here — the corrected source already exists in preview. **Trigger a fresh redeploy** so the latest preview source (null-guard at App.js + iter30 hardening) is built and shipped. After redeploy, verify the served bundle hash changes from `main.6cb17174.js` and that Overview renders for `outlet_id=all` with a global product.

## Optional hardening
Add a React error boundary around the Overview/route tree so a single render throw degrades gracefully instead of blanking the entire SPA.
